SYS.LOG: Sidekick LLM

>_ SYSTEM_SCREENSHOTS

>_ EXECUTIVE SUMMARY

Sidekick LLM is a privacy-first desktop knowledge system built around a durable corpus the user owns. It combines persistent conversations, compounding memory, source citations, and AI Expert vaults trained on private documents and curated research.

The application runs inference through Ollama and keeps chats, embeddings, documents, notes, and settings on the user's machine. Its Electron architecture connects a sandboxed React interface to local model, storage, search, migration, and export services through a narrow IPC boundary.

>_ ARCHITECTURE & SECURITY TOPOLOGY

  • Renderer Process (React 18 + Vite): Handles state transitions, UI rendering, and incremental streaming message updates. Strictly isolated from Node.js APIs.
  • Main Process (Node.js): Orchestrates Ollama communication, persistence, document ingestion, retrieval, migration, and user-data operations.
  • IPC Security Bridge: A context-isolated preload script (preload.cjs) exposes a narrow application API while keeping Node.js capabilities outside the renderer.
  • Knowledge Layer: SQLite, FTS5, embeddings, and per-Expert vaults support conversation search, federated retrieval, citations, memory recall, and portable corpus exports.

>_ CORE ENGINEERING CHALLENGES

1. Reactive Token Streaming over IPC: The Electron main process proxies Ollama's chunked responses across the IPC boundary while the renderer incrementally updates conversation state, giving local inference a responsive desktop experience without exposing host capabilities to the UI.

2. Federated Expert Retrieval: A conversation can consult one or several private Expert vaults. Sidekick searches the selected corpora, combines grounded context with Expert personas, and marks whether an answer used vault knowledge or relied on the model alone.

3. Search and Memory on Local Storage: better-sqlite3, WAL mode, FTS5 indexes, and embedding-backed relevance search support fast conversation lookup, durable facts, and source retrieval without requiring a hosted database.

4. Corpus Integrity and Portability: Versioned migrations, backup-before-migrate behavior, integrity checks, embedding-model mismatch handling, and full corpus export/import protect the long-lived knowledge asset that gives the product its value.

5. Resilient Local Dependencies: Health checks and graceful degradation make Ollama and model availability visible to the user, while first-run guidance connects model choices to system RAM and disk requirements.

>_ ENGINEERING SIGNAL

Sidekick demonstrates desktop security boundaries, local AI integration, retrieval architecture, persistent data design, migration safety, model lifecycle handling, testing, and product-level onboarding in one cohesive system.
